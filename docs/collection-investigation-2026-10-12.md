| 비교 | 전날과 동일 URL | 새로 나타난 URL | 오늘 빠진 URL |
|---|---:|---:|---:|
| 10/9 → 10/10 | 203 | 81 | 444 |
| 10/10 → 10/11 | 219 | 5 | 65 |

81편은 전날 목록에 없었다는 뜻이다. 81편의 신규 발표를 뜻하지 않는다.
444편은 당일 검색/필터 결과에 없다는 뜻이다. 삭제되거나 무효가 됐다는 뜻이 아니다.
새 구현은 URL 비교와 논문 식별 비교를 별도 저장한다. 기존 보고서는 arXiv ID가 없는 동일 제목의
OpenReview 논문과 arXiv 논문을 별개로 세기도 했다. 새 제목 연결 후 고유 수는 과거 수치와 조금 달라질 수 있다.

## 구현 결정과 검증 범위

- 질의 내부에서 잡힌 예외까지 structured telemetry에 기록한다. 최종 질의 결과와 재시도 실패 횟수를 분리한다.
- HTTP 성공 0건, 전체 실패 0건, 의도적인 skip을 구분한다. 잘못된 JSON/XML 구조와 arXiv error feed도 실패로 취급한다.
- 날짜별 JSON에 질의·검색 맥락·논문 식별자·발표일 근거·최초 관측일·전날 변화·경보를 저장한다.
- 신규 발견과 최근 발표를 분리한다. 날짜 미확인, 미래 날짜, 과거 연도/arXiv 월, OpenReview record 시각은 신규 발표 근거로 사용하지 않는다.
- arXiv 주말 검색 창이 갑자기 좁아지지 않게 기본 3일 inclusive 창을 유지하고 월요일에는 금요일까지 확장한다.
- 모든 날짜 기반 수집원에 target_date를 전달한다. S2/OpenReview가 실제 현재 연도로 과거 보고서를 만드는 문제를 제거한다.
- 급변과 부분 실패는 경보이며 원인 판정이 아니다. daily workflow는 strict 경보 발생 시 증거 저장 후 실패로 표시한다.

외부 API에 실제 요청을 반복하는 테스트는 하지 않았다. 과거 요청 제한을 재현하거나 쿼터를 소모할 이유가 없다.
모의 HTTP 오류/재시도/빈 응답/날짜 fallback 및 실제 보존 보고서 URL 비교로 회귀 검증했다.
API 검색은 첫 페이지와 지정 연도 범위만 포함한다. 오래된 원시 응답, 완전한 출판 이력, 임의의 제목 변경은 복원할 수 없다.
Legacy Markdown은 원시 수집/토픽 제외 결과가 없으므로 first_seen은 보존 이력 안의 최초 관측이다.
